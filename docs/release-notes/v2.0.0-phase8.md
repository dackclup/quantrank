# v2.0.0-phase8 — S&P 1500 universe cutover

Released: 2026-06-22

## Headline

The **major-version cut**: QuantRank now ranks the full **S&P 1500**
(~1504 names — ~503 S&P 500 large-caps + ~399 S&P 400 mid-caps + ~602
S&P 600 small-caps) on every weekday cron, up from the S&P 900 pilot.
This is the project's terminal universe by design — QuantRank ranks the
S&P 1500 and deliberately stops there (no Russell 2000 / microcap /
OTC expansion).

The cutover shipped as a **staged 8-slice sequence** so each layer
(small-cap ingest → universe seam → liquidity annotate → cache cold-seed
→ frontend tab → cron flip → Slice-8 hardening) cleared its own
acceptance gate before the next began. The weekday cron has defaulted to
`sp1500` since **Slice 7** (#534, 2026-06-21); `sp900` / `sp500` remain
available via manual `workflow_dispatch`.

Alongside the universe work this release folds a **data-integrity
hardening pass** (XBRL balance-sheet tag selection, dividend / payout
format-reversion guards), the **Slice-8 v2.0 surface** (infinite-scroll
1500-row table, Dividend + Security-type hero tiles, Bonferroni
multi-test shadow counter), and the **research warehouse** (per-run PIT
Parquet snapshots + maximum-history backfill).

Defense layer headline count **36 declared boolean flags** (9 active
vetoes + 27 annotates / reserved) — UNCHANGED across the entire S&P 1500
cutover. The `low_liquidity` annotate (#527, <$5M trailing-30d ADV,
Amihud 2002) was the one new flag in the sequence; it is rank-neutral
(emitted into `valuation_warnings`, never `risk_flags`) and its
veto-promotion decision is deferred pending firing-rate data.

Schema bump → **`0.10.31-phase8pilot`** (MINOR; all-additive nullable
`Metadata` / `StockDetail` fields — no consumer migration).

  `compute/ingest/fundamentals.py::_try_balance_tags`: a 3-tier walk of
  `get_all_facts()` (instant period_type + 10-K/Q form filter + USD unit,
  sorted by period_end then filing_date) replaces the bare `get_fact()`
  delegation that let 8-K / S-type duration facts beat 10-K consolidated
  balance values. Fixes HASI ($1000→$2.5B), LGIH ($25M→$2.1B), GPK
  ($10.8M→$8.4B liabilities). Lands corrected on the next cold
  fundamentals fetch.
- **#554** — `payout_ratio` format-reversion guard (`>20.0 → None`),
  mirroring the #533 `dividend_yield_pct > 100` guard, on all three
  cross-source paths.
- **#533** — removes the `×100` dividend double-scaling (yfinance now
  returns percent directly) + adds the `>100` reversion guard.
- **#552** — drops the free-text post-split `valuation_warning` string +
  corrects stale DQIC docstrings.
- **#553** — `timeout-minutes` 240→270 across the cron / precache /
  pre-merge-sim workflows for S&P 1500 scale.

## Known limitations

- **#555 XBRL fix is cold-fetch-gated** — HASI/LGIH/GPK stay
  cached-corrupt until the next cold fundamentals fetch refreshes the
  frozen-fast-cache for those tickers (filing-date precheck, #471). The
  fix is correct; the cache simply hasn't rolled yet. No action needed.
- **Bonferroni shadow + Security-type tile are observability-only** —
  the `bonferroni_shadow_*` counters and the Security-type metadata
  confirm their firing rate / coverage on forward crons before any
  behavioral wiring (Rule 18). The Dividend tile is live behind its
  coverage canary.
- **`low_liquidity` veto promotion deferred** — KEEP-ANNOTATE (#544);
  promotion to a veto is gated on ≥1 cron of firing-rate data +
  methodology ratification, tracked on issue #544.
- **Slice 8 follow-ups** (epic #545) — virtualized table refinement
  (#540 shipped infinite-scroll), Bonferroni shadow calibration (#542),
  liquidity-veto promotion (#544) continue past the v2.0 cut.
- **15 open `next@14.x` CVEs** — zero exploitability on static export;
  full Next 14→16 migration tracked under issue #41.
